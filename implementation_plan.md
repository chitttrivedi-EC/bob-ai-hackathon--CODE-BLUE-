# D2 Threat Intelligence Correlation & Alert Prioritisation Assistant
## Implementation Plan — Bob AI Hackathon Submission

---

## Overview

Build a complete, end-to-end hackathon submission for problem D2 (Defense & Aerospace track). The system ingests alerts from 4 distinct source formats, semantically correlates them across sources, classifies genuine threats vs. false positives, maps them to MITRE ATT&CK techniques, and produces BLUF summaries via IBM watsonx (IBM Bob integration). A Streamlit dashboard ties it all together.

---

## User Review Required

> [!IMPORTANT]
> **IBM Bob Integration**: IBM Bob's API uses the `ibm-watsonx-ai` Python SDK with `ModelInference` (Granite or Llama 3 family models). The BLUF generation step will call watsonx.ai genuinely — not mocked. You'll need to supply your `WATSONX_API_KEY` and `WATSONX_PROJECT_ID` via `.env` to make this live. Without credentials the app falls back to a structured template so judges can still see the pipeline working.
>
> **MITRE ATT&CK STIX**: The public ATT&CK STIX dataset (~60MB JSON) will be downloaded at first run and cached locally. This is a one-time network hit.

> [!WARNING]
> **No real classified data** is used anywhere. All alerts are generated by a seeded synthetic data generator. The synthetic data is designed to be realistic (plausible IPs, CVEs, geo-coords, timestamps) but is entirely fictional.

## Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                     LANGGRAPH PIPELINE                          │
│                                                                 │
│  [INGEST] → [CORRELATE] → [CLASSIFY] → [MAP ATT&CK] → [BLUF]  │
└─────────────────────────────────────────────────────────────────┘
        │           │              │             │            │
   4 parsers    FAISS+          sklearn      STIX JSON     IBM
   normalize   sent-xfmr      classifier    dataset      watsonx
   → SQLite    embeddings     (RF/SVM)      local cache  Granite-3
```

### LangGraph Stage Breakdown

| Stage | Node Name | Input | Output |
|---|---|---|---|
| 1 | `ingest_normalize` | Raw alert JSON/CSV/CEF/RSS | Normalized `Alert` objects → SQLite |
| 2 | `correlate` | Alert embeddings via sentence-transformers + FAISS | `Cluster` groups with similarity scores |
| 3 | `classify` | Feature vectors per cluster | `threat_score` (0–1), `is_false_positive` flag |
| 4 | `map_attack` | Cluster text → ATT&CK STIX keyword match | List of `TechniqueID` + names |
| 5 | `bluf_generate` | Cluster summary + metadata | Structured BLUF brief via watsonx Granite |

### `src/` — Source Code

#### [NEW] `src/data/generate_alerts.py`
Seeded synthetic alert generator. Produces:
- **SIEM alerts** (JSON, syslog-style): brute force, lateral movement, exfil attempts
- **Satellite feed metadata** (JSON, geo + time): anomalous orbital/positional signals
- **Cyber sensor logs** (CSV/CEF format): IDS/IPS signature hits, anomalous traffic
- **Intel reports** (structured JSON): OSINT-style threat actor bulletins

Includes deliberate **duplicate clusters** (same incident described across 2–3 sources) and **seeded false positives** (plausible-looking but labeled benign). Output: `data/synthetic_alerts.json`. Fully reproducible with `--seed` flag.

#### [NEW] `src/schema.py`
Pydantic models for:
- `RawAlert` (source-agnostic envelope)
- `NormalizedAlert` (unified internal schema: id, timestamp, source_type, severity, raw_text, embedding, cluster_id, threat_score, attack_techniques, bluf)
- `AlertCluster` (group of correlated alerts)
- `BLUFBrief` (structured BLUF output)

#### [NEW] `src/db.py`
SQLAlchemy + SQLite setup. Tables: `alerts`, `clusters`, `briefs`. Migrations handled by table creation on startup.

#### [NEW] `src/pipeline/ingest.py`
Parser registry pattern — one parser per source type:
- `SIEMParser`: JSON with `event_type`, `source_ip`, `severity`
- `SatelliteParser`: JSON with `sat_id`, `lat`, `lon`, `anomaly_type`
- `CyberSensorParser`: CSV/CEF with `sig_id`, `proto`, `bytes`
- `IntelReportParser`: JSON with `actor`, `ttps`, `confidence`

All parsers output `NormalizedAlert`. Writes to SQLite.

#### [NEW] `src/pipeline/correlate.py`
- Load all alerts from DB
- Embed `raw_text` with `sentence-transformers/all-MiniLM-L6-v2` (fast, ~80MB)
- Build FAISS `IndexFlatL2` index
- Cluster with cosine similarity threshold (configurable, default 0.82)
- Assign `cluster_id` to each alert; write clusters to DB

#### [NEW] `src/pipeline/classify.py`
- Feature engineering per cluster: max_severity, source_type_diversity, alert_count, avg_embedding_norm, has_cross_source_match
- Train RandomForest on synthetic labeled data (true threats vs. seeded FPs)
- Persist model with `joblib`; predict `threat_score` for new clusters
- Output: cluster ranked by `threat_score` desc

#### [NEW] `src/pipeline/map_attack.py`
- Download ATT&CK Enterprise STIX JSON once, cache to `data/attack_stix.json`
- For each cluster's combined text, keyword-match technique names/descriptions
- Return top-3 technique IDs + names per cluster

#### [NEW] `src/pipeline/bluf.py`
**This is where IBM Bob (watsonx) is load-bearing.**
- Build structured prompt from cluster metadata (severity, source types, ATT&CK techniques, alert summaries)
- Call `ibm_watsonx_ai.foundation_models.ModelInference` with Granite-3 model
- Parse response into `BLUFBrief` (bottom_line, confidence, techniques, recommended_action, classification)
- Graceful fallback: if no API key → generate template-based BLUF locally (still well-formed, but not LLM-generated)

#### [NEW] `src/pipeline/graph.py`
LangGraph `StateGraph` wiring:
```python
graph = StateGraph(PipelineState)
graph.add_node("ingest", ingest_node)
graph.add_node("correlate", correlate_node)
graph.add_node("classify", classify_node)
graph.add_node("map_attack", map_attack_node)
graph.add_node("bluf", bluf_node)
graph.set_entry_point("ingest")

graph.add_edge("correlate", "classify")
graph.add_edge("classify", "map_attack")
graph.add_edge("map_attack", "bluf")
graph.add_edge("bluf", END)
```

#### [NEW] `src/run_pipeline.py`
CLI entry point: `python src/run_pipeline.py --input data/synthetic_alerts.json --reset-db`

#### [NEW] `src/app.py`
Streamlit dashboard with 4 tabs:
1. **Raw Alerts** — table of all ingested alerts by source type with severity color-coding
2. **Correlated Clusters** — cluster view: which alerts grouped together, similarity score
3. **Priority Queue** — ranked list by threat_score with false-positive badges
4. **BLUF Briefs** — for each top cluster: formatted BLUF card with ATT&CK technique chips
